Motivation & Objectives

Problem Statement & Solution

Existing Manual Systems

  • Manual phone orders prone to communication errors and lost orders.
  • Inaccurate total calculation and lack of itemized price tracking.
  • No real-time transparency for customer order tracking.
  • Cumbersome inventory and menu management for restaurant staff.
  • Lack of operational metrics and sales reporting.

Proposed GourmetBite Solution

  • Automated, self-service food ordering available 24/7 on any device.
  • Strict server-authoritative pricing — client cannot tamper with totals.
  • Live 5-step visual tracking timeline from placement to delivery.
  • Administrator dashboard with real-time gross revenue & status distribution.
  • Full catalog CRUD with instant availability toggles and price controls.
System Engineering

Technology Stack & Architectural Rationale

Backend: Spring Boot & Java 17 LTS

  • Spring Web: High-throughput RESTful controllers with JSON mapping.
  • Spring Security & JJWT: Stateless HMAC-SHA256 authentication.
  • Jakarta Validation: Declarative input validation annotations.
  • GlobalExceptionHandler: Sanitized error responses without credential leaks.

Database: MongoDB NoSQL

  • Document Oriented: Dynamic attributes, allergen tags, and dietary labels.
  • Atomic Snapshots: Cart and Order items stored directly as embedded sub-documents without complex relational JOIN bottlenecks.
  • Indexing: Unique indexes on user email and category names for high performance.

Frontend: HTML5, CSS3 & Vanilla JavaScript

  • Zero External Frameworks: Fast load times, lightweight and accessible.
  • Native Fetch API: Reusable client handling JWT headers and 401 redirects.
  • Responsive Layout: Grid and Flexbox layouts optimized for mobile and desktop.

Quality & Testing: JUnit 5 & Mockito

  • 36 Automated Tests: 100% passing across unit and controller layers.
  • MockMvc: Verifies REST contract and validation errors in isolation.
Data Modeling

MongoDB Collections & Schema Design

Users Collection (users)

Fields: id, name, email (unique), passwordHash, phone, address, role (CUSTOMER, ADMIN), createdAt.

Food Items Collection (food_items)

Fields: id, name, description, categoryId, price (BigDecimal), imageUrl, available (boolean).

Categories Collection (categories)

Fields: id, name (unique), description, imageUrl, active.

Carts Collection (carts)

Fields: id, customerId (unique), items: [{foodItemId, quantity}], updatedAt.

Orders Collection (orders)

Fields: id, customerId, customerName, items: [{foodItemId, foodName, unitPrice, quantity, lineTotal}], totalAmount, deliveryAddress, paymentMethod, paymentStatus, orderStatus, orderDate.

★ Note: Order items store immutable price snapshots to preserve historical accounting.

Business Logic

Order Fulfillment State Machine

Valid Order Lifecycle Transitions

PLACED ➔ CONFIRMED ➔ PREPARING ➔ OUT_FOR_DELIVERY ➔ DELIVERED

Any intermediate stage can transition to CANCELLED. Terminal states (DELIVERED and CANCELLED) cannot be modified.

Cash on Delivery (COD) Automation

When an order is created, paymentStatus = PENDING. Upon reaching the DELIVERED milestone by the administrator, the system automatically advances payment status to PAID.

Cart Auto-Clear Guarantee

The user's shopping cart is atomically emptied only after the order document is successfully committed and validated.

Security Implementation

Stateless Authentication & Role Isolation

Stateless JWT Flow

  • User logs in via POST /api/auth/login.
  • Server verifies credentials using BCryptPasswordEncoder.
  • Issues HMAC-SHA256 token containing claims (userId, role, sub, exp).
  • Client includes token in Authorization: Bearer <token> header.
  • Zero server-side session memory overhead (scales horizontally).

Privilege Enforcement

  • Public registration strictly assigns ROLE_CUSTOMER.
  • Catalog mutations, category creation, order status updates, and dashboard analytics require ROLE_ADMIN.
  • Customer data isolation: Non-admin users can never access or modify another customer's orders or cart.
  • JSON error responses: Unauthenticated requests receive 401; unauthorized requests receive 403.
